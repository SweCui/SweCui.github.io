CMakeLists.txt文件

CMakeLists.txt 是 CMake 的配置文件，用于定义项目的构建规则、依赖关系、编译选项等。通常 CMakeLists.txt 是和源代码放在一起的，每个 CMake 项目通常都有一个或多个 CMakeLists.txt 文件，一般每个子目录下都有一个CMakeLists.txt 用于组织该目录下的文件。针对具体的平台和配置，单独创建一个目录，在该目录下生成特定平台和配置的工程文件，做到工程文件不会和源代码文件混搭在一起。

继承

子目录的 CMakeLists.txt 自动继承父目录里的 CMakeLists.txt 所定义的一切宏、变量。极大地减少了重复的代码。

语法

CMakeLists.txt 文件使用一系列的 CMake 指令来描述构建过程，语法非常单纯，由指令(command) 和注解所组成，每个指令可有零至多个参数。使用指令的语法为指令名称加上小括号，括号内可以有零或若干个参数，指令则依照出现在CMakeLists 当中的顺序执行。所有的空白、换行、tab 都没有特殊作用，仅为语汇元素的区隔。

变量和缓存

CMake 使用变量来存储和传递信息，这些变量可以在 CMakeLists.txt 文件中定义和使用。

变量可以分为普通变量和缓存变量。

变量具有以下特征：

变量严格区分大小写！

CMake 中的变量只有两种类型：字符串，和字符串数组。

变量无需声明即可赋值或者使用。未赋值的变量默认为一个空字符串。

与其他语言编程语言不同的是，CMake 脚本的语法中没有赋值操作。无论是赋值，还是比较、判断操作，都是通过内置指令来完成的。

变量可以认为都是全局的，哪怕在一个宏中定义的变量，也可以在宏的外面被访问到。

局限

CMake 并不遵守 GNU 规则。这使得 CMake 对一些开源软件的支持不够。

例如：CMake 生成出的工程在 Linux 下不支持 make uninstall。

CMake 和其他编译系统会打架，处理起来不容易。

例如：如果不用 Qt 自带的QMake，而是用 CMake 去编译 Qt 工程，会很费时费力。

CMake 不会认识开发者在 IDE 中新增加的文件。必须通过修改 CMakeLists.txt，才能让 CMake 知道有新的文件。
